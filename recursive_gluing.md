## 1. Research objective

The environment should evaluate whether a coding agent can implement a general solution to problems with all three properties:

1. **Recursive self-similarity:** a large problem is assembled from smaller instances generated by recurring structural rules. The hierarchy may be deep, and subproblems may participate in cyclic dependencies rather than forming a simple tree.
2. **Hidden reparameterization:** locally equivalent structures use different state labels or coordinate systems. Copying a solution from one component to another without transporting it correctly is insufficient.
3. **Nontrivial global consistency:** locally valid solutions must agree across overlapping interfaces. Every component may be individually solvable, and every neighbouring pair may be compatible, while the entire system still admits no globally consistent assignment.

The intended research question is whether models can recover and use structural invariants that make recursively assembled problems tractable, rather than relying on shallow search, memorized labels, or independent solutions to local components.

The conceptual inspiration is self-referential puzzles, recursive composition, and the local-to-global consistency ideas behind the existing `cat_theo/sheaf/` environments. The logarithm's conversion of multiplicative self-similarity into additive translations is one motivating example, but do not restrict the environment to complex numbers or logarithmic transformations.

For this initial implementation, use a **finite-domain, exact, machine-checkable core**. Do not attempt to implement separate dice, SQL, distributed-computing, and theory-of-mind environments in this task. They are possible future instances of the broader research programme, not scope for this first implementation.

## 3. Environment structure and mathematical contract

Use the environment name `recursive_gluing`, located at:

`envs/cat_theo/recursive_gluing/`

The environment should present a code-repair task in which the agent must complete or repair a solver that returns a globally valid assignment, or correctly reports that no assignment exists.

Use a finite collection of local regions. Each region has a finite set of locally valid states. Different regions may use different labels for states that correspond structurally. Overlaps specify which pairs of local states are compatible. A complete assignment must select one state per region while satisfying every local restriction and every overlap constraint.

Generate the regional structure recursively from a small set of reusable templates. The resulting structure must contain nested levels and, at appropriate difficulty levels, cycles and cross-level overlaps. Do not merely attach a depth field to an otherwise flat instance: recursive generation must affect the actual constraint structure.

A useful exact mathematical model is:

- Each region \(i\) has a finite domain \(D_i\).
- Each overlap between regions \(i\) and \(j\) specifies a relation \(R_{ij}\subseteq D_i\times D_j\).
- A global assignment \(x\) is valid precisely when \(x_i\in D_i\) for every region and \((x_i,x_j)\in R_{ij}\) for every overlap.
- Some instances have valid global assignments; others have none, even though individual regions and selected adjacent pairs are locally satisfiable.

The generator may construct overlap relations from hidden permutations of a shared finite carrier. Do not expose a canonical global labelling that trivializes the task. Represent the observable data using local labels and correspondence information. Ensure that random relabellings preserve the underlying task's answer.

Include instances exhibiting a genuine global obstruction: locally valid states and pairwise-compatible neighbours, but no assignment satisfying the entire cyclic constraint system. Also include solvable cyclic instances. The agent must distinguish the two.

The solver's output contract must be explicit and deterministic. Reuse the repository's normal submission interface where possible. The judge must validate the returned assignment directly against the complete instance, or validate a no-solution result against an independent exact oracle.

Do not trust the agent's prose explanation as evidence of correctness. Do not accept merely locally valid outputs.

## 6. Independent oracle and scoring

The hidden judge must use an independent correctness path, not reuse the candidate solver to determine the expected answer.

Check separately:

1. Valid solution assignments satisfy every domain, local restriction, and overlap constraint.
2. Solvable instances are solved, including cyclic cases.
3. Unsatisfiable instances are correctly identified as such.
4. Arbitrary local relabellings leave correctness unchanged.
5. Held-out recursive depths and state-space sizes work within a clear time bound.
6. Outputs are deterministic in the specified way and malformed outputs fail safely.

For small instances, an independent exhaustive oracle is acceptable. For larger instances, use a separate exact oracle or independently implemented propagation/search procedure with tractable complexity. Explain why the oracle is complete for the supported input class. Never treat a timeout, parse failure, or internal error as proof that no global solution exists.

Include adversarial cases where every local component is solvable but the total system is not. Include counterexamples to naive strategies such as solving every region independently, copying local labels, checking only a spanning tree, and ignoring the remaining cycle constraints.

Avoid hidden tests that are merely larger copies of the same easy case. Keep both positive and negative instances, and ensure the score is not dominated by easy conditions.

Use the repository's existing scoring mode and result schema. Prefer explicit machine-checkable criteria over a vague continuous score, while preserving compatibility with the existing judge infrastructure.
