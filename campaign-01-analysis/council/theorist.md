# Theorist — separate analysis

## Strongest supported interpretation

The epistemic-games result is the cleanest formal measurement in the archive, but its formal target is narrower than its narrative. The task fixes two behavioral policies, their likelihoods, a prior, one observed announcement, and a likelihood-ratio vocabulary. The model supplies a posterior and labels; the judge re-derives the same instance from the seed and checks the answer. All seven selected rows passed all recorded posterior, direction, verdict, provenance, and consistency checks. The exact audited outcomes include posterior values of one half for uninformative balanced-prior items, three fifths for an uninformative skewed-prior item, one fifteenth for a strong-evidence item, and ninety-two over one hundred seventy-seven for a weak-evidence item. This supports a bounded claim of correct Bayesian calculation on seven fixed, specified-policy cases.

It does not support the claim that the model recursively reasoned about a strategic agent. `core.py` says v0 does not implement a full level-k process with utilities and recursive belief updates. The level-3 story is attached to a fixed evidence table and mimicry invariant. A mathematically honest description is “Bayesian inference over specified policies presented in a genuine-versus-strategic narrative.” The model could have applied Bayes' rule, inferred the intended policy from the supplied probability table, or used a learned pattern; the output alone cannot identify its internal route.

The rest of the campaign is best understood as a mixed set of code-repair probes with different operational meanings. A passing lens-law check is not evidence of general categorical competence; passing the regex Rule 110 task is evidence that the returned program met that judge's constraints on its tested strings, not that the model discovered a “weird machine” substrate. In several category-tagged tasks, the source template or judge does not instantiate the advertised mathematical law. The labels are useful prompts for engineering tasks, not warrants for theorem-level claims.

## What the capability map can mean

The outcomes suggest heterogeneous local competence rather than a scalar ordering. The recurrent-depth totals are 31/33 after excluding neither case; but the exact-reference subset is `rd_state_carry` at 11/11, while `rd_gradient_credit` is 11/11 compile-only and `rd_adaptive_halting` is 9/11 compile-only. One `rd_adaptive_halting` failure is an indentation error and another is a runtime mask dtype error. Those are observed patch/evaluation outcomes, not a clean curve over recurrence depth. The category track's 57/84 eligible pass count mixes 5 behavioral-reference cases and 79 compile-only cases, and the archive's track assignment incorrectly places the seven epistemic items in `ml_debugging`. After source-semantic regrouping, the three ML-debugging environments contribute 9/30, not the recorded 16/37. None of these aggregates is a common cognitive scale.

The strongest weird-machine contrast is the regex task: at the easy surface class name, all three string lengths pass; with the medium and hard class names at the easy string length, both fail with length-expansion errors. This is an observed pattern, but `hard` also adds a performance comment, and the manipulation changes class names. CSS and SQL show nonmonotone patterns that include source-validator failures. The theoretical object is therefore a response profile under specific prompt/config/judge combinations, not evidence that surface deception generally dominates hidden depth.

## Claim ceiling and falsifiers

I would publish three kinds of claims only: exact archive facts; local task outcomes with judge mode and failure type; and a modest interpretation that selected prompt/task transformations sometimes coincide with large outcome differences. Do not call the mixed 131/192 proportion a validated benchmark score. Do not say “the model has ToM,” “the model understands category theory,” or “a weird-machine capability was demonstrated.”

A follow-up capable of supporting a recursive-reasoning claim would generate the behavioral policies from explicit utilities and alternating belief updates, hold the surface constant, vary recursion depth and information structure independently, and use randomized instances with more than one seed. A follow-up capable of supporting a surface-effect claim would compare semantically equivalent, matched prompts with class names and hints independently randomized, run repeated trials, and preserve the same hidden judge. Both proposals are future experiments, not retrospective reinterpretations of these results.
