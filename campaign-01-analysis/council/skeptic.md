# Skeptic — separate analysis

## The headline denominator is not stable until provider failures are audited

The common 131/193 framing excludes the one outage episode that `campaign_report.json` names. It does not exclude a second final result whose judge note is explicitly `provider transient failure after bounded retries`: the easy/easy `sheaf_physical_constraints` case. That row is recorded as `invalid_action` even though its final note attributes it to provider retries. The defensible accounting is to show raw 131/194 PASS, then state both exclusion sensitivities: 131/193 if only the report-listed case is removed, and 131/192 if all terminal provider-coded results are removed. If authors report only 131/193, the case-level artifacts contradict their stated exclusion rule.

Even 131/192 is not a uniform score. The report says compile-only results are exploratory. It is a mixed fraction across case judges; it should not be used as a model-wide “accuracy” or compared across tracks without the exact judge-mode split. The recorded track summary also mislabels all seven Bayesian epistemic items as ML debugging, inflating the raw ML-debugging pass share from the source-semantic 9/30 to 16/37.

## The manipulation is weaker than the axis names

The source audit is damaging to several controlled-perturbation narratives. The `compositional_optimizer` config varies `MODEL_CLASS` and `LR_VAL`, but its source templates contain neither placeholder: task, starter file, visible test, and judge name `MomentumStep`. The five nominal cells therefore do not support a naming or symptom-mask effect. `categorical_lenses` declares `STRICT_LAWS` but the template files never reference it; the judge always checks all three laws. The source scan identifies additional category axes (`CHECK_DIM`, `SYMMETRY_DIM`, `AUG_PARAM`, `SIDE_EFFECT_CHECK`, `TOLERANCE`, `SIGMA_VAL`, `UNICODE_SUPPORT`) with no direct references. If the executed tree matched the clean snapshot, these are not implemented interventions. The campaign's dirty-source flag prevents making that last sentence certain about the paid run, but it also prevents using the nominal manifest as proof that the manipulation occurred.

The category track cannot be read as categorical reasoning. It has 57/84 eligible passes, but only five are behavioral-reference cases and the rest are compile-only. Its `compositional_optimizer` prompt claims an associativity/multi-step task, while the judge checks one chain's state isolation. The physical constraints task imposes a 5:3 ratio absent from its prompt and visible tests. The lens judge samples one fixed-seed tuple and law checks rather than a structural or exhaustive object-level test. The benchmark labels are not independent theoretical verification.

The weird-machine result is also fragile as a causal story. In the regex task the medium/hard surface class names coincide with the two failures, but the hard case also receives an extra performance hint; one model run per cell cannot rule out sampling variance or a specific class-name cue. CSS and SQL contribute nonmonotone cells but include disallowed-import and syntax errors. Hidden-depth values are string length, bit count, graph chain length, or spreadsheet grid length—not a unified depth construct. A title can say “surface deception” only if its subtitle makes these limits unmistakable.

## Scalar labels conceal protocol and judge events

All 24 eligible `patch_invalid` rows have empty patch files. Ten `source_invalid` rows are syntax/disallowed-import outcomes, and three `runtime_error` rows are execution outcomes. The two rows labeled `overfit_visible_tests` instead have trusted scores of 1.0 and notes that a required companion file was missing. These labels should not be rewritten as cognitive failure types without source checks. There are two provider-terminal failures in the raw `invalid_action` bucket; leaving them there makes API availability look like an agent's invalid action. A single zero can therefore mean no patch, policy rejection, parse failure, runtime crash, or a task answer that misses tests.

The archive also records `reasoning_enabled=false` but 325,785 reasoning tokens and 2,710 rows with reasoning content. That is a metadata inconsistency, not evidence about a model's cognition; do not reproduce private reasoning text or interpret the counter as a clean experimental treatment. Retry totals similarly conflict across run manifests, API logs, suite checkpoint and progress records. Cost is absent.

## What survives skeptical review

The individual case results and their exact judge checks survive: seven `epistemic_games` cases were scored perfectly, and the source says those cases compute posteriors over stipulated policies rather than recurse over strategic beliefs. The four weird-machine environments retain a documented response pattern under the observed code; the regex string-length invariance at easy surface is a real within-run result, though not a generalized law. The exact 194-row checkpoint count, 24 omissions, config hash matches, repeated-run inventory, final judge notes, and API counters are reproducible archive facts.

The strongest available article is not “Atria reasons recursively, sees hidden computation, or masters category theory.” It is “one completed Atria-Dawn-Preview sweep contains a heterogeneous pattern of exact task outcomes, with meaningful differences between task/judge families and several implementation/provenance defects that constrain the score.” That claim can be falsified by a clean re-extraction that disagrees with the row-level tables or by a verified dirty source tree that changes the comparator findings. Any causal claim about surface, depth, or difficulty needs a repaired, replicated design.
